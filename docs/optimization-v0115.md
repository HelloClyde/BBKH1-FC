# 0.1.15 三国志2等待循环 HLE

普通版基线为 0.1.14，BDA SHA-256：
`ad8989bc948052b2fe8c452c201188ba6cf9903c287c6321417a61a4290f2235`。
最终 0.1.15 BDA 为 1,137,672 字节，SHA-256：
`b5cbff7b03f5b0a0980ccf422669279030ce907cd7944c36d914821bec3a1dd9`。

本轮实现的是已知 ROM 等待循环的语义替代，不是通用 Mapper 19 游戏逻辑 HLE。
Namco 163 的 bank 映射、IRQ 计数和音频本来就在核心中以行为级方式实现。
卡带接口并不规定所有游戏共用同一个音乐驱动或游戏逻辑接口。

## 优化对象及边界

用户提供的 SGZ2-CN ROM SHA-256 为
`7b4fcd1c0be33e69943dcf9c81cca67bac634a9de2881aa2f3d8f9b6a3864117`。
PRG 与 CHR 各 256 KiB，PRG+CHR 的加载器 MD5 为
`de319a7a8099c388810c59cb038e8c9d`。自动准入同时检查 mapper、大小与该内容校验。
固定 PRG bank 31 的 CPU 地址 `$FB28` 对应物理 PRG `$3FB28`：

```asm
FB28: LDA $62
FB2A: BNE $FB28
FB2C: RTS
```

`$62` 由游戏的 Namco IRQ 处理程序清零，不能把等待直接跳到 vblank。
原版本城市 300 帧共执行 2,573,039 条 6502 指令，其中这个循环占 582,670 条，
即 22.6452%。循环的生成 MIPS 部分占完整城市指令量 6.244%，还未包括共享 C 分发。
该比例使用已补全解释器快慢时钟路径的观察结果；早期 23.27% 的分母不完整，已标记废止。

HLE 只折叠两个及以上完整的非零等待迭代，每轮 6 个 CPU 周期。它同时受原 CPU 预算、
APU 帧事件、DMC 事件及 Mapper IRQ 截止时间约束；不移动 PPU 扫描线或寄存器同步点。
待处理 IRQ、DMC DMA、超频、未知观察钩子、ROM 页或读取函数变化、代码字节不符等
情况全部返回原指令执行路径。待清零标志仍由原 IRQ 代码实际更新。

结束时保留原 A/P/PI/DB、预算、时间戳及分支余留的 `tcount=1`。
分发器下一 PC 为 `$FB28`，但下一次时钟回调之前，CPU 结构中的 PC 必须仍是上条
BNE 的 `$FB2A`。这项中间可观察状态也纳入差分测试，不能只比较最终存档。

只命中该 ROM 时，JIT 解码在 `$FB28` 停止，静态链接也不进入该点；动态入口因为
不存在此处的原生块，同样返回 C 分发。这样临近事件时回退执行原指令后，还能再次
尝试 HLE，避免原生回边一直绕过它。其他 ROM 的编译覆盖保持原策略。
三个常数商改用精确的无符号乘积高位与移位，最终反汇编确认没有该路径的 `DIVU`。
没有扩大 JIT 缓存分配，也没有改动音频波形或跳过游戏逻辑。

## 完整应用结果

实际运行最终普通 BDA，使用同一空初始存档、输入脚本
`tests/scenarios/sgz2-newgame-city.json`、缩放 1、声音开启和音量 100。
流程为 1800 帧，城市操作窗口为 1501–1800。包含加载、编译、显示、PCM、周期存档、
暂停菜单及正常退出；固件服务由测试器模拟。

| 跳帧 | 0.1.14 完整指令量 | 0.1.15 完整指令量 | 整段减少 | 城市段减少 |
| --- | ---: | ---: | ---: | ---: |
| 1（默认） | 3,873,307,353 | 3,661,620,585 | 5.4653% | 3.8946% |
| 0 | 4,561,187,512 | 4,349,500,744 | 4.6410% | 3.2905% |

城市段跳帧 1 从 661,217,984 降至 635,466,079；跳帧 0 从 782,621,430 降至
756,869,525。两档均逐帧严格核对 LCD、CPU/PPU 与全部声明状态、源 PCM，另核对
播放环、显示节奏、追赶次数和最终存档。不能把这些指令量比例换算成真机 FPS 或断音改善。

首版只有 C 入口识别，跳帧 1 整段减少 5.0900%、城市减少 3.6181%；最终路由和常数商
改进在此基础上继续降低成本。首版已覆盖 79.52% 的等待指令，88.08% 的成功批次
受原 CPU 切片限制，每批平均 7.676 轮，因此这段 HLE 的剩余空间有限。
这些覆盖率仅属于首版，不能冒充最终版的覆盖率。

最终完整流程日志记录 262,142 个 HLE 批次、1,998,929 轮、11,993,574 个 CPU 周期。
生成代码使用 5,902,656 字节，无代码池回卷；BDA 比基线增加 1,424 字节。

## 验证与重现

- `tests/hle_wait_smoke.py`：最终产物 505 例全部通过，含 150 个正向 HLE 断言和
  111 个拒绝断言；覆盖 CPU、APU/DMC/Namco 事件、回调中间状态、损坏读档和换 ROM。
- `tests/hle_routing_smoke.py`：18 例入口检查通过，包含原生顺序流、JSR/JMP/RTS、
  条件分支和间接入口；未命中 ROM 仍能编译相同地址的普通块。
- 闭式状态的独立推导在 4,036 个实际 MIPS 解释器用例中通过。常数商另有全部
  uint32 输入域的证明，以及 2,143,203 个边界和随机精确商对照。
- 冻结源码构建与工作区标准重建 BDA 逐字节一致。最终关于页、日志、元数据版本均为 0.1.15。
- 完整 H1 固件的首次启动和同 NAND 重启验收通过，分别运行 522/250 帧，视频错误和
  退出结果均为零；32 kHz 音频、暂停恢复、关于页、退出桌面与跨启动读档通过。
  原固件 494 个文件、941,764,502 字节前后哈希一致，使用私有 NAND。
  固件运行只检查生命周期，不代替物理 H1 的性能测试。

机器证据见 [optimization-v0.1.15.json](evidence/optimization-v0.1.15.json)。
长流程原始记录位于 `build/verification/v0115-final-city-skip{0,1}.json`；
首版覆盖率及纠正记录为 `build/verification/v0115-hle-coverage-summary.json`。
商业 ROM、固件、私有 NAND 与采集 PCM 均不放入安装包。

## 魂斗罗对照改变了下一步的判断依据

用户提供的《魂斗罗》确认为 Mapper 2，当前版本走解释器，原生 JIT 指令数为零。
同一 0.1.14 BDA、相同显示和声音设置下，第一关 300 帧执行 828,823,378 条 MIPS
指令，比三国志2城市还多 25.35%；用户却报告它在真机上更流畅。
这是不同游戏与执行路径的比较，不能隔离 Mapper 因果，但足以说明指令量不是充分指标。

后续需要在同一 H1 上补充实际周期、帧耗时与音频欠载测量，再判断 JIT 代码局部性、
指令缓存、访存和 PPU 工作是否是主要成本。当前没有证据确认缓存失效就是根因，
也不能继续把 Mapper 19 的扩展声音笼统当作主要瓶颈。
详见[魂斗罗控制实验](contra-mapper2-control.md)。
