# 0.1.14 条件分支周期批处理与 OAM 校验区间

本轮基线为冻结的 0.1.13 普通版，BDA SHA-256：
`c4f7c7efe035e25752c8ac6fbb13d0775a16d459cb97c7555eed4768c1f9fc1c`。
源码、构建脚本、测试及 BDA/ELF 已保存在 `build/v0114-baseline`，每项有哈希清单。
最终选定条件分支基础周期批处理和 OAM 校验区间；默认跳帧 1 的完整应用
指令量比基线减少 **4.75%**，城市操作段减少 **4.51%**。这是最终组合的实际执行结果。

## 设计与顺序

第一阶段先尝试扩展条件分支后的顺序编译轨迹，但完整应用收益不足，未采用。
保留原编译块边界，把条件分支的固定基础周期并入前面的安全纯操作区间，
减少短块内重复的时钟和事件调度。跳转额外周期在基础批次提交后继续留在
`tcount`，由下一次原事件推进处理；回边也只能在提交后进入经过准入的目标。

短预算仍以实际执行条数判断分支是否已执行，不能以 PC 是否等于顺序地址判断。
对于两条指令的条件分支短块，整段准入失败或事件前缀只完成第一条时，剩余指令
继续使用原来的单指令预算、事件与失效守卫，保留原生连接能力。
不扩大 IRQ/DMC 的无事件证明范围，不省略可观察的操作数读取。
整段和前缀准入的待修补跳转分别保存，避免与普通退出地址共享临时槽位。

本轮不重复上一版已测得退步的首指令周期门槛，也不直接合并 PPU 的短 CPU 时间片。
例如 6 周期后执行的水平地址重载以及扫描线切换都是可观察事件；更大的预算不能
代替准确的事件边界。优化对象是这些边界之间的不必要分发工作。

冻结版的只读调用普查确认：城市 300 帧调用 `X6502_Run` 共 289,800 次，
其中 51,536 次仅有最短单指令预算，31,733 次在结转后没有正预算。
6 个 PPU 周期的调用占 72,000 次，其中 30,063 次没有正预算。
观察器逐帧核对原状态、LCD 和 PCM，没有补丁修改客体执行。
这些频次用于选择候选，不直接当作可省去的调用数或预估收益。

第二阶段处理 PPU 数据路径。先检查稳定 OAM 的重复全量比较是否可以按真实写入和
状态恢复失效，再评估同一行精灵合成、颜色处理的重复遍历。所有缓存均为派生状态，
写入、复位、成功或失败的状态加载和不透明钩子必须恢复正确的重验路径。
保留动态精灵压力场景，不以静态城市场景的收益掩盖明显退步。

## 验收契约

- 分别测量 JIT 候选、PPU 候选，再测最终组合；不相加独立收益。
- 实际执行普通 BDA 的完整应用，包括加载、编译、CPU/PPU/APU、显示、PCM、
  周期电池档、暂停菜单与正常退出。诊断包的计时不能作为普通包收益。
- 使用同一三国志2 ROM、空初始存档和 `tests/scenarios/sgz2-newgame-city.json`，
  完整流程 1800 帧，城市段为第 1501–1800 帧，分别检查跳帧 1 和 0。
- 同核心必须逐帧核对 LCD、源 PCM、CPU/PPU 和全部声明状态，另核对播放环、
  显示节奏、追赶计数和最终存档；任何差异先解释或修复，不直接归为性能收益。
- JIT 专项覆盖条件跳转两边、内部/跨页目标、短预算、分支附加周期、DMC/IRQ、
  自修改代码与 bank 变更；PPU 专项覆盖中途寄存器、CHR/OAM 和状态恢复边界。
- 最终冻结产物还要在完整 H1 固件模拟器验证有声播放、暂停恢复、存档和退出。

所有性能比例均指执行的 MIPS 指令量，尚不能直接换算成物理 H1 的周期、FPS
或音频连续性。原 0.1.13 完整应用基线为跳帧 1 的 4,066,529,729 条、
跳帧 0 的 4,754,409,888 条；城市段分别为 692,412,446 和 813,815,892 条。

## 独立候选记录

以下均为普通 BDA、跳帧 1、完整 1800 帧；正值表示减少执行指令。

| 候选 | 完整应用减少 | 城市段减少 | 决策 |
| --- | ---: | ---: | --- |
| 同页有界条件分支顺序轨迹 | -0.0694% | -0.0521% | 增加成本，弃用 |
| 仅前向分支轨迹并拆开 IO 侧出口 | 0.0289% | 0.0735% | 收益不足以支持新增复杂度，弃用 |
| 外层周期结转与空预算返回 | -0.0325% | -0.0218% | 检查成本抵消收益，弃用 |
| 条件分支基础周期批次，保留事件慢路径原生连接 | 1.2642% | 1.0375% | 采用 |
| OAM 在写入后重新验证 | 3.4873% | 3.4677% | 采用 |
| 精灵合成与行颜色处理融合 | -0.1878% | -0.1373% | 增加成本，弃用 |

上述六组均严格通过逐帧状态、LCD、源 PCM、播放环和存档比较。
OAM 在每 13 个 CPU 周期写 `$2004` 的动态压力 ROM 上仍有约 0.35% 的稳态
指令增量，这是独立 PPU 候选的成本；最终组合在同一压力 ROM 上减少 **2.03%**。
两个结果不能混为一谈，也不能据此保证所有游戏都会更快。

首版条件分支基础周期批次在独立随机 CFG 差分中失败：CPU 预算结束时错误清除了
尚待下一条指令处理的 `tcount`。该产物的完整应用运行已中止，不采信性能数据。
失败用例保留；修正后的 v4 候选和最终 0.1.14 分别以新哈希重新进行边界及完整应用验证。

## 收益来自哪里

扩展顺序轨迹会增加编译、入口检查和代码缓存压力，省下的分发成本不足以抵消它们。
最终 JIT 没有扩大编译块，而是减少现有短分支片段内的重复事件、预算和时钟处理。
两指令块遇到事件时继续采用原生逐指令路径，保留 DMA/IRQ 和失效出口。

三国志2完整流程的原生调用从 2,055,560 到 2,056,040，基本不变；原生链接从
365,094 到 364,834，不能声称本轮大幅减少了分发次数。已用代码池从
5,326,688 到 5,906,368 字节，仍在既有 8 MiB 池内，两边均无回卷。
JIT 堆分配规模不变；普通 BDA 增大 2,632 字节，静态 BSS 大小不变。

PPU 沿用精灵行索引，但取消无写入区间内每行重复比较 256 字节 OAM。
所有 `$2004` 写入（含 DMA）、复位、状态加载、帧边界和未知观察者都会撤销该区间。
损坏状态文件可能在报错前已写入 OAM，因此在读取状态块前也失效。
未知钩子即使修改 OAM 后自行卸载，下一次仍必须重新校验。
内容改变时保留线性扫描，稳定后才建立索引；CHR 取数、优先级、溢出和 sprite-zero
行为保持原顺序。CPU/PPU 同步时间片没有移动。

## 正确性与固件验证

最终普通 BDA 的 12 套 CPU 检查全部通过：4,833 例 opcode、964 例短预算、
1,260 例子程序/栈、232 例事件、1,374 例定向分支、864 例随机控制流、
155 例组合时钟、入口/PPU/递归契约、6 例活跃代码池检查，以及 932 例 bank
边界和两个 Mapper 各 16 帧。相关原生路径断言保留，没有用回退解释器掩盖问题。

PPU 的 29 帧失效边界、29 帧缓存恢复、32 帧动态 OAM、100,000 例主机取数
差分通过；诊断插桩的合成时钟语义与计账检查、6 例默认配置检查也通过。
所有专项绑定最终 BDA；没有借用版本字符串不同的产物作证据桥接。

普通版在完整 H1 V1.41 固件模拟器通过有声标题、暂停恢复、关于页、退出桌面，
并在同一私有 NAND 重启成功读档。首次/重启显示 492/246 帧，视频错误与退出结果
均为零，两次音频欠载均为零；这些短固件运行不是音频流畅度或真机性能证明。
原固件目录 494 个文件、941,764,502 字节前后哈希一致。

诊断构建的游戏生命周期、保存和退出也通过，但**重启验证的细分计时未通过**：
计数器从前值 65464 回卷到 14，重读仍未取得 FULL 标志，命中原读钟策略的
`pc_fault=2`，诊断保护关闭细分计时。首次运行的 TCU 校验正常；不能据此忽略
重启失败，也不能使用该次细分耗时。读钟源码本轮未改，确定性复现仅证明旧策略
也拒收这组输入，尚未确认硬件或固件层原因。机器证据分别记录普通版验收和
诊断计时失败，**本次不提供 0.1.14 诊断安装包**。普通版及上述指令量对照不受影响。
