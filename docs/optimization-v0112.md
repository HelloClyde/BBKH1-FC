# 0.1.12：内存传输与短预算分发

基线为 0.1.11 正常版，SHA-256：
`4062e52a9b3881a8e41fda3c831064e1ff28573a8552e0e54283b8d4aee2a302`。
本轮先测独立候选，再测合并后的完整应用。默认跳帧 1、旧配置保留、
返回键默认映射 B，以及 8 MiB JIT 代码缓存均保持原行为。

## 采用的改动

对齐的 `memcpy` 增加 64 字节展开循环，摊薄行缓存和显示复制的循环控制成本；
保留 16 字节、4 字节和逐字节尾部，未对齐地址继续使用原逐字节路径。
`memcmp` 在两边均按 4 字节对齐时每次比较 16 字节；相等则继续，
不等时回到逐字节比较，返回第一个不同的无符号字节之差。
不读取请求长度以外的数据，也不增加堆分配或数据缓存。
本轮没有新增 MXU 指令，已有线性缩放 MXU 路径保留。

CPU 的剩余预算不超过 96 内部单位（2 个 CPU 周期）时，只可能开始执行一条指令。
这类调用直接走已有 C 解释路径，省去进入和离开原生 JIT 的成本；
预算大于 96 时继续使用原分发条件。整条指令超出预算后的时间结余、
IRQ、DMC、Mapper/APU 事件与总线访问协议均保持原样。
这不是省略指令或降低时序精度，也没有移动 PPU 的同步点。

城市 300 帧的调用计数中，289,800 次 CPU Run 调用有 31,733 次预算已耗尽，
51,536 次只够一条最短指令，约占 17.78%。现有扫描线在 `Fixit2`、
精灵处理、行刷新、emphasis 采样和 Mapper 回调附近有可观察的同步边界。
因此本轮只去掉短预算下的多余分发成本，没有直接合并相邻 Run 调用。

## 完整应用对照

同一《三国志 II》ROM、1800 帧新游戏/城市操作脚本、相同配置和空初始存档。
包含加载、编译、CPU/PPU/APU、显示、音频供给、周期存档、暂停菜单和退出。
城市段为第 1501–1800 帧。以下为最终 0.1.12 正常版 BDA 的实测结果。

| --- | ---: | ---: | ---: | ---: |
| 0 | 4,975,326,376 | 4,861,653,197 | 2.28% | 2.28% |
| 1（默认） | 4,213,065,242 | 4,148,630,576 | 1.53% | 1.52% |

跳帧 1 城市段从 722,465,598 降至 711,508,460；跳帧 0 从 859,679,959
降至 840,073,533。逐帧 LCD、源 PCM、声明状态、播放环、存档和显示节奏严格一致。
两档均有 660,352 PCM 帧、91 音频追赶帧；跳帧 1 为 886 显示帧，跳帧 0 为 1,740。

## 未采用的 JIT 实验

尝试在普通 opcode 读取前直接检查已编译块入口，保留原生入口的映射/版本校验，
并在零执行回退时重新读取正确的 opcode 和 handler。修正数据总线可观察值后，
严格差分通过，但整段仅减少 0.2066%，城市段反而增加 0.1135%。
64 帧核心单独测量减少 0.782%，不能代表完整应用城市流程。
这条更复杂的快速分发路径没有进入正式 BDA，实验与报告保留在本地 build 目录。

## 验证

- 最终 BDA 的内存函数共 5,169 例：624 例复制、2,844 例比较、1,701 例重叠移动。
  覆盖双方 0–3 字节对齐、循环和尾部边界、首个不同字节、返回指针与完整目标缓冲区。
  记录 1,523,161 次源读取，均在请求范围内。
- JIT opcode 差分 4,657 例，覆盖 87 个 opcode，保留原单指令短预算测试，
  另用足够预算断言确实执行原生块，避免新阈值导致测试只走 C 路径。
- 短预算专测 684 例：阈值前后、空预算、PAL/NTSC、跨页、栈、PPU/APU 写入、
  IRQ/NMI、DMC、Namco 和上一条指令时间结余；完整序列化状态一致。
- 事件期限与原生块连接差分 232 例；入口约定测试保留短预算与原生路径的独立覆盖。
- 最终 BDA 的 38 例显示行缓存生命周期、内容变化和申请失败检查通过。
- 默认跳帧及旧配置保留、返回键映射、暂停菜单、存档 IO 故障处理和音频恢复通过。
  22.05/32/48 kHz 输入的实际 PCM 函数检查通过；慢显示场景仍执行全部 20 帧 CPU/APU，
  临时跳帧不改写用户配置。

内存测试的 Unicorn 全局写 hook 会使未修改的基线在分支延迟槽字节写入时也报错。
因此测试采用源读取 hook 与完整目标缓冲区哨兵核对写入结果；这是测试器限制，
不是将候选代码的失败忽略。读取地址按物理地址与 KSEG 映射统一后计数。

关于页（NES / v0.1.12 / HelloClyde）和正常退出，并在同一私有 NAND 重启后读档成功。

原始固件目录 494 个文件、941,764,502 字节前后哈希一致，没有修改原始镜像。

诊断包首次标准日志提取返回 12,557 字节 FF。保留失败文件后，对唯一遗漏的已提交
部分 NAND 单元检查头尾与逐页标签，以只读方式恢复出 181 条连续日志；
NAND 恢复前后哈希一致。这是该单元的取证恢复，不是通用提取器修复。

诊断包首次暂停恢复后出现 TCU 读取故障（`fault=2`），细分计时报告标为 `fault=3`；
受影响的 TCU 耗时无效，RTC 运行计数仍标为有效。该次诊断包记录一次音频欠载，
正常包首次记录为零；不能将不同模拟运行的欠载次数当作性能对照。
诊断包同 NAND 重启的标准日志提取直接成功，TCU 故障为零、RTC 有效，欠载为零。
计时器与 RTC 实现本轮没有修改。
本版收益仅取正常包的独立指令计数，上述诊断计时没有进入收益结论。
