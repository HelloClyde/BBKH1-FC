# H1 FC v0.1.5：MIPS32 JIT v3 实验版验证

当前产品名称为 **NES**，安装文件为 `H1NES.bda`。本文记录改名前的 JIT v3 性能与固件验证，
原始证据中的名称和 SHA-256 保留不变；此前改名见[命名变更记录](evidence/name-change.json)，
当前桌面名称缩短见[校验记录](evidence/name-shortening.json)。
此次仅调整 BDA 标题、关于页和安装包命名，没有更改模拟核心。

自动加速仍限于 Mapper 0 / 19 的已确认代码块；
其他指令、mapper 和不适合编译的块使用解释器。
见[整体设计](jit-design.md)与[本轮优化边界](optimization-v3.md)。

## 完整应用性能

使用本地 SGZ2-CN，三版均为相同 ROM、空初始存档、相同输入，scale=1、skip=0、sound=1、volume=100。
直接执行 release BDA 共 600 帧，最后通过普通 Escape 事件正常退出。
统计包含启动、加载、CPU/PPU/APU、编译、显示缩放、PCM 队列、输入、等待、退出存档和资源释放。
固件服务由测试器模拟，其内部执行成本不计入；数据是 MIPS 基本块指令入口数，不是真机周期或 FPS。

| 构建 | 600 帧完整应用指令量 | 相对普通解释器减少 |
| --- | ---: | ---: |
| 保留的普通解释器 | 2,653,630,733 | — |
| 上一版 JIT v2 | 2,412,824,548 | 9.07% |
| 本版 JIT v3 | 2,223,330,763 | **16.22%** |

本版比上一版 JIT v2 进一步减少 **7.85%**。第 241–600 帧的有声标题阶段，
v2 的 1,465,122,254 降至 1,339,113,252，减少 **8.60%**。
每 60 帧的分段数据与完整文件哈希见[机器可读证据](evidence/jit-experimental.json)。

截图确认覆盖 Namcot 开场和《三国志 II 霸王的大陆》标题动画、音乐，未进入战斗。
首次非零 PCM 在第 88 帧；此前仅 20 帧的应用测试属于静音启动，不能代表有声运行阶段。
三版的 600 帧 LCD、完整源 PCM、CPU/关键 PPU 字段、退出存档及提交/实际读取的环形 PCM 均一致。
长测试的状态摘要不是完整序列化状态；核心差分另行验证完整状态。
600 帧尚未到运行中自动存档周期，因此只证明退出存档路径。

## 优化内容与归因

- PPU 固定 4 字节填充在 freestanding 构建中原本反复调用 memcpy。改为显式 builtin，
  MIPS 直接生成有界访存并保留未对齐行为。背景像素使用两个对齐 32 位写入，颜色、灰度、
  emphasis 合并遍历，固定精灵和 palette 拷贝内联。fetch、滚动、mapper hook 和 sprite 命中顺序不变。
- JIT 从 71 扩展到 **87 个 opcode**，覆盖 ADC/SBC、绝对 RAM 写、绝对索引读、INC/DEC、间接 JMP。
  IO 写调用原 handler 后必须结束块。动态读取校验真实目标和 dummy 地址；保留原核心跨页周期、
  DB、PC、A/P 与间接指针回绕。纯 RAM/CartBR 读取直接生成访存，间接 JMP 可连接跨 bank 热块。
- C 回退事件调度增加 Namco IRQ 无事件内联路径。APU、DMC、IRQ 仍在每条指令原边界更新，
  到期调用原处理函数，不延后事件或替换等待循环。相同 PPU/JIT 的独立消融测试中，
  32 帧核心为 87,893,799 → 87,727,671，收益约 0.19%，没有把小收益夸大为主要来源。

PPU 单项隔离测试中，普通解释器 SGZ2 前 32 帧从 114,541,862 降至 103,597,019（9.55%），
CPU 指令量不变。最终全部改动的同一核心片段为 87,727,671；
该核心测试替换了前端，不能与完整应用混用。

600 帧应用里，CPU wrapper 与生成代码合计从 711.29M 降至 685.05M（3.69%）。
wrapper 单独下降很多是工作转入原生代码，不能宣传成 CPU 总收益。
PPU 行处理及复制/比较开销进一步下降；缩放仍为 463.82M，未在本轮更改。

## 正确性验证

- 最终 BDA 通过 **2,809 组后端、232 组事件/连接、451 组寻址/总线差分**，共 3,492 组。
  其中 102 组检查 callback 可观察总线顺序，覆盖 IO 改寄存器、预热后继重映射、动态 handler、
  IRQ/NMI 延迟、DMC DMA、跨页、缓存回收、状态恢复、申请失败与退出释放。
- 367,592 组 PPU 数据路径比较覆盖未对齐填充、全部 PPU mask 组合和随机 tile 路径。
- 实际 MIPS 整帧比较 CPU/PPU、完整序列化状态、存档、画面和 PCM，包含 SGZ2、原创 sprite-zero/overflow、
  跳帧、DMC 循环 DMA、DMC IRQ、PAL、Mapper 2 解释器回退。
- 10 MiB 代码池构建实际执行 16 帧并保持状态、画面和 PCM 一致，入口表另占 1 MiB。
- 默认代码池 1 MiB、入口表 1 MiB；600 帧代码池使用 921,888 字节，无回收。
  执行 4,603,392 条原生 6502 指令、65,725 次块连接；一次失效回退没有产生状态或输出差异。

生产自动准入与 force 后端测试分开；force 覆盖不代表生产支持所有 mapper。
长基准缓存核对 ROM、BDA、ELF、设置和事件。修改测试器语义后须更新 SCHEMA 或重新生成缓存。

## 完整 H1 固件模拟

最终包使用用户持有的 H1 固件副本及 QEMU bbkh1，原始 dump 未修改。
普通包显示 1,066 帧，录到约 5.016 秒非零 32 kHz 音频，恢复后另录 2.009 秒；
profile 包显示 914 帧，分别录到 5.000 和 2.007 秒。
暂停、继续、触摸/实体键关于和退出回桌面均通过，关于显示 MIPS JIT v3 / HelloClyde，桌面图标背景透明。
两版 APP_END=0、QEMU 退出码 0；profile TCU fault=0。

**两版均记录 1 次音频欠载。** profile 定位到启动期第 23 批，缺少 289 个输出采样（约 9.03 ms）；
暂停恢复后未增加，drop/failure 均为 0。不能据此宣称零欠载或卡顿完全解决。
600 帧固件服务模拟基准中的零欠载仅属于该测试环境，与完整固件结果分别记录。

## 真机复测

先安装普通 JIT 包，以相同 ROM 和显示设置比较声音。诊断包可记录 20–30 秒后的 A:\FC\h1fc.log，
重点看 AUDIO_GAP、AUDIO_CLOSE、PROFILE_COST / PROFILE_WINDOW、JIT_CACHE 和 JIT_LINK。
profile 本身增加计时开销；没有 H1 真机结果前，不把指令量下降换算为 FPS 或断音改善保证。
