# 0.1.13：子程序边界、短区间调度与 PPU 精灵处理

性能基线为冻结的 **0.1.12 普通版**，SHA-256：
`a8f7304365aae6379b343546938da4eb003f1e8255deb7a51eaff4a03e37c615`。
先分别测量 JIT 和 PPU 候选，再测最终合并的普通版完整应用。
诊断日志用于判断优化顺序，诊断包的计时不用于计算本轮收益。

## 采用的设计

JIT 增加 `PHA/PLA/JSR/RTS`。子程序调用和返回可以连接已有编译块，
保留栈地址回绕、数据总线 DB、PLA 标志位以及 JSR 的低操作数读取、
压入返回地址、高操作数读取顺序。动态返回目标仍经过代码页及版本校验。
单条指令的入口仍使用解释器，不放开最少两条指令的编译规则。

固定周期的 JMP/JSR/RTS 可以成为安全区间的末尾，与纯 ROM/直接 RAM 前缀
共用执行预算和时钟提交。完整区间保留实际目标 PC，短预算按实际执行条数
判断末尾是否已执行；不能用“PC 恰好等于顺序地址”代替执行判断。
区间中的回边须先提交时钟，再进入原有块连接。事件临近、IRQ、DMC 和不透明
回调继续使用原时序路径。没有合并 PPU 的 CPU 同步点。

PPU 精灵合成按四个像素处理透明与优先级，扫描范围限制在当前精灵覆盖区域，
保留原完整行缓冲区、裁剪、sprite-zero 和消费顺序。
取精灵时按完整 OAM 内容和精灵高度复用可见行索引，仍按照原优先级读取
当前 CHR 映射；有 PPU hook 时保留原循环。OAM 或高度变化先更新快照并回到
线性扫描，连续两次内容相同才建立索引，避免频繁改写时反复重建。
加载旧状态后也按内容重新验证，不把派生索引写入游戏存档。

普通版静态 BSS 增加 **2,192 字节**，text 增加 **3,120 字节**。
JIT 代码池仍为 8 MiB，加入口表、bank 索引和验证表约 9.41 MiB，未增加堆分配规模。
默认跳帧 1、保留旧配置、返回键映射 B、音频采样率与存档策略保持原行为。

## 独立实验与取舍

以下为跳帧 1 的普通版独立候选，比较同一 1800 帧流程；城市段为最后 300 帧。

| 候选 | 完整流程指令量减少 | 城市段减少 | 处理 |
| --- | ---: | ---: | --- |
| 仅增加子程序/栈指令 | 0.2349% | 0.4583% | 继续合并控制流末尾预算 |
| 子程序/栈指令 + 控制流末尾批次 | 0.3935% | 0.7250% | 采用 |
| 上项另加跨块寄存器保留入口 | 0.4147% | 0.7449% | 未采用额外入口 |
| 原版另加首指令周期准入门槛 | **增加 0.2119%** | **增加 0.1960%** | 未采用 |
| 选定 JIT 另加首指令周期门槛 | 0.2340% | 0.6048% | 比选定版本慢，未采用 |
| 精灵合成 + 带动态回退的 OAM 索引 | 1.5855% | 1.9588% | 采用 |

跨块寄存器保留入口只比选定 JIT 多减少约 0.0212 个百分点，却增加约 196 KiB
运行时代码及额外入口协议，因此没有合入。首指令周期门槛的额外分发检查抵消了
省去短块的收益，正式版保留原 `_count <= 96` 策略。
选定 JIT 的已用代码池从 4,419,456 增至 5,326,688 字节；原生链数量增加，
原生调用总数也增加，不能把覆盖率或链数量的增长单独当作提速。

未保护的 OAM 索引在每 13 个 CPU 周期写一次 `$2004` 的压力 ROM 中，
稳态核心指令量增加 31.67%，因此弃用。保护后的独立 PPU 版本增加 1.10%，
保留有限的快照与判断成本；不保证所有动态精灵场景都更快。
背景输出 `restrict` 实验在 64 帧核心测试中增加约 0.089%，也没有合入。

## 计量边界

完整应用对照执行实际普通版 MIPS BDA，固件服务由测试器模拟，包含加载、编译、
CPU/PPU/APU、缩放显示、PCM 供给、周期存档、暂停菜单和退出。
输入使用 `tests/scenarios/sgz2-newgame-city.json`，初始存档为空，
缩放 1、声音开启、音量 100；跳帧 0 和 1 分别与相同设置的基线比较。
商业 ROM SHA-256 为
`7b4fcd1c0be33e69943dcf9c81cca67bac634a9de2881aa2f3d8f9b6a3864117`。

指令量不等于物理 H1 的周期或帧率；缓存、内存总线、固件和同步 IO 耗时
仍需真机验证，不能据此宣称已经全速或消除音频欠载。

## 正确性与固件验证

- 91 个支持 opcode 共 4,833 例差分，另有 964 例短预算和 1,260 例子程序/栈/
  控制流区间检查，包含实际原生执行断言、栈/PC 回绕和目标等于顺序地址的边界。
- 232 例事件期限、155 例组合时钟，及入口凭据、PPU IO、递归回调和活跃代码池
  生命周期检查通过。Bank 缓存 932 例边界与两个 Mapper 各 16 完整帧通过。
- 精灵合成 315,536 例、取精灵索引 100,000 例主机差分通过；实际 MIPS 的 29 帧
  PPU 恢复测试包含 4 次旧状态加载、8/16 高度和跳帧 0/1/2 切换。
  合并版动态 OAM 压力 ROM 的稳态指令量增加约 1.09%，输出严格一致。
- 诊断模式的实际 MIPS 核心差分验证完整状态、PCM、图像及计账平衡；默认跳帧、
  旧配置保留和显示菜单恢复默认检查通过。

两项旧测试原本只给 1 或 6 个 PPU 周期，未越过此前已有的 96 单位 JIT 门槛，
却要求编译或有效凭据。冻结 0.1.12 也复现相同失败。修复测试时保留原短路径
阴性验证，再以 7 个 PPU 周期断言真正进入原生路径；未删除原状态、期限和复用断言。
另一项 DMC 故障注入曾在批量时钟提交的内部写入点插入状态变化，已移至真正的
APU 期限回调入口，保留两边同周期、恰好一次、DMA 次数和全部状态检查。

首次构建遗漏了两处硬编码版本文字，固件测试发现后已修正。
修正前后普通/诊断 BDA 各仅有两个只读 ASCII 字节从 `2` 变为 `3`；
全部可执行/可写节、节布局和符号地址一致。
上述 opcode、短预算、子程序三组及 PPU 恢复/动态压力/诊断计账检查使用此前产物，
通过该逐字节证据桥接；没有把它们声称为修正包实跑。
其余 CPU 专项、两档完整城市对照和以下完整固件验收均实际运行最终修正包。
构建现在会拒绝 VERSION 与编译后的日志/关于字符串不一致的产物。

普通包与诊断包均在完整 H1 V1.41 固件模拟器通过标题流程、有声播放、暂停恢复、
关于页、退出至桌面及同私有 NAND 重启读档。首次/重启显示帧分别为普通
522/242、诊断 460/184，视频错误和退出结果均为零。
关于页确认 `NES / v0.1.13 / HelloClyde`，四份日志均由标准提取工具直接取得。
诊断两次运行的 TCU 故障均为零、RTC 有效，五种细分模式均出现有效记录。
诊断两次各记录一次音频欠载，普通两次为零；不同固件模拟运行不能用于计算性能收益。
原固件目录 494 个文件、941,764,502 字节前后哈希一致。
固件覆盖标题流程，城市性能来自前述独立完整应用对照；尚未进行物理 H1 验收。
