# FCEU320 与 H1 NES 0.1.13 的完整应用对照

发布范围：本文是本地独立实验的历史记录。v0.1.16 不分发 FCEU320 对照适配器、生成工具或其专用测试；它们不参与正式 FCEUmm 应用构建。文末命令记录的是当时本地实验入口，不能仅用本版公开源码直接复现。以下实验数字及产物哈希保持原记录。

本实验回答：把成熟 Dingoo 掌机核心接到同一套 H1 前端，是否比当前实现更省计算。
参考为 FCEU320 的固定提交
`6e4da0b45fbff14fc374c5da38a84463cdabe634`，不是直接执行 Dingoo 原厂二进制，
也不是 JZ4740 真机速度测试。比较产物仅用于实验。

结论：本次同前端、同 ROM、同城市输入下，移植 FCEU320 没有减少执行指令。
默认跳帧 1，正常 PPU 版整应用指令量比当前普通版多 63.44%，
启用上游快速跳帧后仍多 29.67%。因此本轮保留当前核心；没有覆盖正式安装包。

## 对照设计

- 正式基线：0.1.13 普通 JIT BDA，SHA-256
  `c4f7c7efe035e25752c8ac6fbb13d0775a16d459cb97c7555eed4768c1f9fc1c`。
- 解释器控制组：相同 0.1.13 源码、PPU/APU 优化及前端，只关闭 JIT。
- FCEU320 正常 PPU：运行上游正常扫描线处理，跳帧时不呈现图像。
- FCEU320 快速跳帧：启用上游 `FRAMESKIP`，允许其近似可见区处理。
  该路径会近似 sprite-zero hit、强设 sprite overflow，不能视为精度相同的优化。

使用同一《三国志2》中文 ROM（SHA-256
`7b4fcd1c0be33e69943dcf9c81cca67bac634a9de2881aa2f3d8f9b6a3864117`），
同一个 `tests/scenarios/sgz2-newgame-city.json` 输入脚本与空初始存档。
全流程 1800 帧，城市段为第 1501–1800 帧。通过正常固件按键队列输入，
最后打开暂停菜单并选择退出，不补丁跳过应用初始化、退出或核心执行。

共同设置为缩放 1、声音开启、音量 100、源采样率 22050 Hz、低质量混音、
关闭低通、8 精灵限制，以及同一套 H1 32000 Hz PCM 播放接口。
两边使用相同的索引图像缩放、LCD、按键、音频供给、周期电池档与菜单代码。

## 如何计量

执行真实普通版 MIPS BDA；文件、计时器和设备服务由既有 H1 测试器模拟。
主机计数器只观察执行块，不修改游戏代码、寄存器或核心内存。
在 `FCEUI_Emulate` 的实际入口与返回处记录核心指令量，其余归为外围处理。
入口/返回计数扣除尚未执行的当前块，避免统计边界偏差。

新增观察器已与此前 0.1.13 的跳帧 0/1 各 1800 帧记录严格核对：
逐帧指令量、LCD、PCM、显示节奏和完整应用输出完全一致。
因此本次新增的成本拆分没有改变基线执行工作。

指标是 **MIPS 指令量**，不能直接当作 H1 的运行周期、FPS 或音频连续性。
代码大小、指令缓存、内存等待和固件服务的真机成本仍需实测。

| FCEU320 快速跳帧 | 5,273,075,465 | 增加 29.67% | 870,661,339 | 增加 25.74% |

跳帧 0 的补充对照：

两档的源 PCM 均为 660,352 帧，追赶计数均为 91；跳帧 1 显示 886 帧，
跳帧 0 显示 1,740 帧。各组最后均到达 189 年 1 月同一城市命令界面，
金 190、米 280、人口 21000、武将 3、兵士 2100；最终 8320 字节电池档 payload 相同。
这些证明本次输入推进到同一场景，不代表两个核心所有中间时序、颜色或声音完全等价。

默认跳帧 1 的快速版，核心指令量为 4,828,067,493，比当前版多 33.41%；
外围为 445,007,972，比当前版少 0.57%。因此这次差距集中在核心内部，
不能归因为 H1 菜单、缩放或 PCM 前端。这里的核心范围包括 CPU、PPU、APU 和 Mapper，
这次计量不能进一步把新增成本准确分配给四者。

## 移植边界与公平性

CPU、PPU、APU、N163 扩展音源、Mapper 19 银行切换和 IRQ 执行代码保留上游实现。
桌面的 SDL、电影录制、调试、截图、压缩包与菜单服务由固定配置的 H1 适配层代替。
电池档仍收集 Mapper 的 8192 字节 WRAM 与 128 字节 IRAM，并通过现有 H1 存档管理器保存。

默认调色板使用上游原函数在主机预生成，五套默认调色板各 512 色；
O0/O2 输出逐字节一致。这样无需在裸机补入近似数学库。
这改变了启动时的调色板初始化成本，城市段不受这项预计算影响。
VRC7 的固定表也由原初始化器预生成并做声音差分验证，SGZ2 不使用 VRC7。

以下差异必须保留在解释中：

- 旧核心的 CPU RAM 开机填充值与 FCEUmm 不同，没有为追求哈希相等而改写。
- 混音舍入、N163 系数计算和调色板算法不同，跨核心 PCM/LCD 哈希不要求相等。
- 采用 H1 的逐行强调色显示契约，不能把它称为原 Dingoo 显示驱动的性能。
- 快速跳帧有精度取舍，需要检查实际城市画面和输入进度。
- 实验适配层不提供即时存档、自定义调色板或 NTSC 调色界面；不能视为通用发行版。
- 实验关于页的版本行标明 `FCEU320 test`，但继承的核心/致谢文字仍含 `FCEUmm`；
  本轮冻结产物未再修改。实际核心身份以构建清单、BDA 哈希和 `core=FCEU320_compare`
  启动日志为准，该 UI 文案需要在任何未来分发前修正。

跨核心结果同时记录画面、PCM、按键、显示/追帧次数、电池档与正常退出，
必须确认实际进入相同城市操作阶段，才接受其场景覆盖。

## 移植正确性检查

独立审计核对了固定上游源码与两份冻结 ELF：每版 349 个源码文件逐字节保留，
12 个文件为明确的移植适配；CPU、APU、滤波器和 N163 等关键执行文件未改。
PPU 仅追加位反转查找表的生命周期辅助函数，原执行源码完整保留。
实际链接产物保留 N163 合成、IRQ 和 Mapper 19 银行写入路径。

- 实际 MIPS 执行全部四个 C++ 全局构造函数，并核对 256 项位反转表。
- 连续两次初始化/释放均无残留分配；两版各 32 帧输入、音画、菜单退出测试通过。
- OPLL 固定表与原初始化算法比较 480,000 个声音样本，完全一致；CRC 24 组通过。
- 两版在独立目录重建，BDA、ELF、BIN 均逐字节相同。

冻结 BDA：正常 PPU 版 453,160 字节，SHA-256
`d8d86edce5f648d4d893271323d7b22fd6ee9505a54536b0840fbeea7b86b404`；
快速跳帧版 453,512 字节，SHA-256
`2ab67eae7dd25edb36490069fda8bd63f5d33ec1bdd75912ced8c14d02c3d95b`。

完整 H1 V1.41 固件模拟器分别执行了两份冻结 BDA，覆盖 ROM 选择、标题、
有声播放、暂停恢复、关于页和退出桌面；两版首次运行视频错误、音频提交失败与
应用欠载均为零。该测试不等于物理 H1 的连续音频验收。
城市流程的性能数据来自前面的独立完整应用测试器。

两版随后均用同一份各自的私有 NAND 重启，成功读取上次电池档，重新输出声音并正常
保存退出。原始固件目录 494 个文件、941,764,502 字节前后哈希一致；
生产源码与正式产物的 60 项预先快照全部未变。完整汇总与证据哈希见
[机器可读验证记录](evidence/fceu320-comparison.json)。

## 对下一步优化的含义

本次实验不支持整体替换成 FCEU320，也不能据此推断 Dingoo 真机运行 FC 很慢。
它测量的是移植到同一 H1 前端后的 MIPS 指令工作量，并未覆盖原掌机的频率、缓存、
驱动和固件环境。当前 JIT 加已有 PPU/APU 优化已经比这个参考移植更省指令。

下一步仍应针对当前核心：先减少频繁短预算造成的 JIT 分发往返，再扩大可安全批处理的
PPU 区间。前者要把运行期限与可观测事件统一起来；后者必须保留 Mapper、DMC、
PPU 寄存器访问和精灵命中的可见时序。FCEU320 的快速跳帧可以作为单独的精度取舍
实验，不能直接替代严格等价的默认路径。本轮仅完成核心对照，没有把这些后续设计
声称为已实现收益。

## 历史本地复现入口（不随本版分发）

先取得上述固定版本 FCEU320 源码；默认位置为
`build/jz4740-reference/fceu320`，也可给构建器传 `--source`。

```powershell
python tools/build_fceu320_compare.py --variant conservative
python tools/build_fceu320_compare.py --variant fast
python tests/fceu320_app_benchmark.py --bda build/fceu320-compare-fast/H1FC.bda --elf build/fceu320-compare-fast/H1FC.elf --label fceu320-fast --skip 1 --frames 1800 --rom build/audio-baseline/sgz2-cn.nes --input-script tests/scenarios/sgz2-newgame-city.json --output build/verification/fceu320-reproduce-fast-skip1.json
```

将 `fast` 替换为 `conservative`、`--skip 1` 改为 `--skip 0` 即可运行另三组，
并为每组指定独立输出文件。先核对重建 BDA 哈希，再与冻结基线比较；
ROM 使用本地提供的相同文件。完整命令和结果索引见
`build/verification/fceu320-complete-app-summary.json`。

构建器只输出 `build/fceu320-compare-*` 下的实验 BDA/ELF。
完整本地证据保存在 `build/verification/fceu320-*`；商业 ROM、固件和采集音频不分发。
