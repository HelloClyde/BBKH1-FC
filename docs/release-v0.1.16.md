# NES v0.1.16

作者：**HelloClyde**。适用于步步高 **H1 / Y100 V1.41**，继续作为预发布提供。
这是相对上次公开版 v0.1.2 的累计更新，重点是游戏速度、声音连续性和正常存档。

## 主要变化

- **默认使用优化 C 执行路径。** 多款游戏的真机对照显示，原生 JIT 即使减少模拟指令量，
  仍可能运行得更慢。默认对所有 ROM 关闭原生代码分发，保留既有事件调度、PPU/APU 优化、
  严格身份匹配的三国志2等待循环 HLE，以及其他 Mapper 的保守回退。
- **改善声音恢复。** 缓冲不足时临时减少画面输出，恢复后回到用户的跳帧设置；
  只统计近期重复欠载，避免早先的断音让后续一直维持过高跳帧。默认跳帧为 **1**，
  即每两帧显示一帧，CPU、音频和游戏逻辑始终逐帧运行。
- **减少保存造成的周期停顿。** 同长度的备用存档槽优先原位更新，保留双槽、CRC、
  关闭后重新打开及完整数据校验。对严格匹配的三国志2中文版，周期变化检查排除
  已验证的 12 个音乐寄存器字节；实际提交仍写入全部数据，游戏进度变化仍会保存。
  同步写盘仍可能短暂停顿，并未改成后台存档。
- **累积的显示与核心改进。** 合并调色板转换和缩放，复用稳定背景及 OAM 精灵索引，
  优化声音合成和事件调度；保留碰撞、Mapper、DMA、状态恢复与未知回调的必要边界。
  修复精灵观察者修改行缓冲后，范围裁剪可能遗漏像素的问题。
- **操作调整。** 桌面和关于页名称缩短为 **NES**。游戏中的退出／返回键默认对应 **B**，
  不再退出模拟器；P 或触摸画面打开暂停菜单，再选择“退出游戏”。旧配置迁移保留其他设置。
  未选择 ROM 时取消仍直接返回桌面，保留透明图标和菜单确认键防穿透修复。

原生 JIT 保留为显式 `--native-jit` 实验构建，加入通用纯 NOP 块拒编、编译抖动退避和
间隔探测。它不能保证比默认 C 更快，也没有硬实时探测上限；普通使用无需开启。
旧 `--jit` 参数仅为构建命令兼容，不再启用原生执行。

## 真机对照说明

以下为开发期间已经核验的短窗口：**旧 v0.1.12 PROFILE 前端 + RAM 中的新核心**。
测量窗关闭 profile 开关，但旧包装代码仍在；这不是最终 v0.1.16 BDA 的整包安装测试。
各窗保持跳帧 1，声音追赶可进一步降低显示帧率。欠载是该窗口内的计数增量。

| 游戏与场景 | 执行方式 | 窗口 | 模拟帧/秒 | 显示帧/秒 | 音频欠载 |
| --- | --- | ---: | ---: | ---: | ---: |
| Final Lap 赛车 | 通用原生 JIT | 30 秒 | 17.29 | 2.89 | 323 |
| Final Lap 赛车 | 同一核心关闭原生分发，使用 C | 30 秒 | 60.09 | 30.06 | 0 |
| Rolling Thunder 首关 | NOP 实验版原生 JIT | 10 秒 | 42.96 | 9.18 | 94 |
| Rolling Thunder 首关 | 同一核心关闭原生分发，使用 C | 10 秒 | 60.14 | 28.54 | 0 |
| 魂斗罗首关实玩 | 通用 C；该 Mapper 不使用原生块 | 30 秒 | 60.08 | 26.93 | 0 |

Final Lap 使用同一即时存档和预先按住的油门，较快的一窗推进了更多游戏时间。
Rolling Thunder 的 C 窗末端已死亡重生，不能视为两窗执行了完全相同的工作量，
也不据此计算等工作量加速比例。魂斗罗另核验了实际单人游戏与移动，排除了演示和 Game Over 窗口。
这些数据支持默认选择 C，但不证明所有游戏、全部场景或长时间运行都能全速。
约 60 模拟帧/秒受限速影响，不能推算剩余 CPU 性能。

另外，Final Lap 的纯 NOP 拒编实验仍只有约 27.63 模拟帧/秒；独立退避实验在完成适应后的
30 秒窗口达到约 60.11 模拟帧/秒且未欠载。后者不是最终“纯 NOP 拒编 + 退避”组合实验包的
整包真机验证，因此没有据此把原生 JIT 设为默认。

最终默认 BDA 已通过完整 H1 V1.41 / QEMU 固件验证：From Below Classic 实玩 848 帧，
画面错误为 0；移动、旋转、落块、暂停、恢复、关于页及正常退出通过。暂停前后均采集到非零 PCM，
日志音频欠载为 0。空 ROM 目录连续取消两次均返回桌面，原始固件文件前后校验一致。
最终 BDA 尚未安装到物理 H1；上述真机 RAM 实验与本次整包模拟验证分别记录。

完整版本身份、最终 BDA 验证和公开精简数据见 [发布证据](evidence/release-v0.1.16.json)。
实际 MIPS 差分用于检查 CPU/PPU/APU 状态、PCM、画面和存档是否一致，不能代替物理帧率测量。

## 下载与升级

下载 `BBKH1-FC-v0.1.16-install.zip`，将 `应用`、`FC` 文件夹合并到设备 A 盘：

```text
A:\应用\程序\H1FC.bda
A:\FC\H1FC-TEST.nes
```

启动桌面的 **NES**。包内只附原创测试卡带；商业游戏 ROM 不随安装包或源码分发，
请自行提供有权使用的 `.nes` 文件。无需 BIOS，也不支持直接打开 ZIP。

升级前备份 ROM 旁的两个电池槽、即时存档和配置文件。存档格式及路径保持不变。
已有 `H1NES.bda`、`H1FC-JIT.bda` 等旧实验入口可在确认新版本可用后移除，避免重复图标；
不要删除游戏或存档。默认安装文件虽然名为 `H1FC.bda`，桌面标题仍是 **NES**。

`H1FC.bda` 为单独应用文件；`BBKH1-FC-v0.1.16-source.zip` 包含应用和两个固定子模块的源码。
使用 `SHA256SUMS.txt` 核对下载文件，`release-manifest.json` 记录构建与验证身份。
不附固件、设备内存转储、私人存档或本地调试模块。

固定依赖保持不变：SDK `067fe072477861dfc8949d7b1a55279fb92d2548`，
FCEUmm `ac0d00a7fc01166f84c7bac01d1084ebfd2b865e`。
开发者默认构建运行 `python tools/build.py`、`python tools/package.py`；
依赖安装及验证命令见 [README](../README.md) 和 [开发说明](development.md)。
