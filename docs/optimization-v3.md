# JIT v3：按完整应用优化

## 验收边界

对照是已交付的 JIT v2 二进制，另保留普通解释器作为语义基线。
使用本地《三国志2》ROM，相同初始存档、按键、缩放、音量、采样率和零跳帧运行。
完整应用包含 ROM 加载、CPU/PPU/APU、缩放、PCM 队列、输入、等待、存档与正常退出。
旧的 20 帧测试仍用于回归，但该片段尚未输出非零 PCM，不能代表有声游戏阶段。
新增较长的 release BDA 测试按 60 帧分段，同时比较逐帧 LCD、PCM、CPU/PPU 状态及存档。

指令量是实际 MIPS 程序在 Unicorn 中进入基本块的结构成本；不是 H1 实测耗时或 FPS。
CPU 核心测试替换了前端回调，不能直接把其中 `retro_run` 的 RGB565 回退转换成本
算成完整应用的瓶颈：正式应用已经使用 indexed 视频通道。

## 三个模块共用的设计约束

1. **PPU 数据路径**：tile fetch、滚动、mapper hook、sprite-zero 命中和 overflow 的顺序不变。
   优化 tile 像素打包、固定长度拷贝和最终行颜色转换，减少 MIPS32 不适合的 64 位操作与多遍扫描。
2. **事件调度**：每条 6502 指令仍在原来的位置提交周期。已经到期的 APU/DMC/DMA 与 IRQ
   交给原处理函数；已核对的 Namco IRQ 未到期路径直接更新计数。C 回退和原生路径采用同一边界规则。
   不跨越 IO、IRQ 或 DMC 边界累计跳过指令，不以延后声音事件换取表面速度。
3. **JIT 覆盖**：优先覆盖真实 ROM 热循环中的寻址与控制流。纯 RAM/ROM 操作可留在原生块；
   会改变 PPU、APU 或 mapper 的 IO 访问必须先提交 CPU 状态，并在访问后结束当前块。
   每次新取指重新验证代码映射；保留开放总线、跨页附加周期、6502 间接跳转回绕和中断延迟。

JIT opcode 数量只描述覆盖范围。是否保留一项改动由差分正确性与完整应用净成本共同决定。
代码缓存占用、编译成本和频繁退出同样计入，不能只比较生成代码内部的操作数。

## 验证分层

- 纯像素函数与固定上游做数据差分，覆盖 palette、灰度、emphasis 和跳帧时的 sprite-zero 条件。
- 真实 MIPS 后端逐 opcode、跨页、handler/mapping 变更、缓存回收和状态恢复差分。
- 事件到期前/当时/之后分别检查原生和 C 回退路径，包括 DMA、IRQ 阈值与 16 位回绕。
- 原始诊断 ROM 检查 sprite-zero/overflow、DMC、PAL 与不准入 mapper 的回退。
- 《三国志2》完整 release 应用逐帧比较并统计有声场景，截图只用于确认实际覆盖场景。
- 最终安装 BDA 使用完整 H1 固件检查启动、音频、暂停恢复、关于菜单和退出；结果绑定文件 SHA-256。

ROM、固件、游戏截图、音频和存档仅保留在本地忽略目录，不进入安装包。
