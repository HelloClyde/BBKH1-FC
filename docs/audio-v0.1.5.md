# 0.1.5：参考君正掌机移植后的优化

本次在 v0.1.4 的本地开发版本上继续实现可保留游戏行为的优化；参考依据见
[JZ4740 源码对比](jz4740-fc-reference.md)。v0.1.5 普通包没有 JIT，
[JIT 方案](jit-feasibility.md) 单独记录了参考项目、实际 opcode 统计和后续接入门槛。

## 修改

- FC 索引像素、每行强调色和 RGB565 调色板直接参与最终 LCD 输出，省略完整的
  256×240 RGB565 中间图转换及读写。最近邻模式使用小型调色板、列映射和行映射缓存；
  线性模式直接生成缓存扫描行，继续使用原有整数插值和 MXU 垂直内核。
  原调色板 RGB565 量化、强调色、边框、滤波舍入保持一致，未将 H1 LCD 改成 16 位。
- 跳帧时省略精灵颜色展开/合成；保留精灵零号的实际位掩码以及精灵评估和溢出标志。
  背景 tile 仍取数、更新滚动地址并调用 Mapper 钩子；只有无需输出且没有待判断的
  sprite-zero hit 时省掉像素打包。没有采用 FCEU320 强制设置碰撞标志的近似跳帧。
- 音频欠载时保留当前持续播放描述符。已消费的数据分两段清零；所有有效 PCM
  都被消费后才移动写位置，留出 512 样本（16 ms）静音余量，并对后续 128 样本
  （4 ms）作整数淡入。正常混音不加这层处理；暂停、退出或无效队列仍正常取消播放。
- 提供可单独试验的 `--optimize O3` / `--lto` 构建选项及元数据。LTO 下运行库
  保持独立编译，避免编译器后期生成的 memset/memcpy 调用失去定义。备用 RGB565
  路径的 256 KiB 颜色表移到按需系统堆分配，退出释放；分配失败时使用直接颜色计算。
  O2/LTO 与 O3/LTO 均已编译成功并进行了核心差分。普通成品保留 O2，尚未用实机确认 LTO 的净收益。
  各变体的核心生成目录相互独立，修复并行试编译互相覆盖准备中源码的问题。

## 验证

普通 BDA SHA-256：`51d805b05c6cb834a5ca4a6b6c6eda2efe2257e8e1deb56acecbfbb3cc1a13e5`。

诊断 BDA SHA-256：`dfe796745dbc68dcf7e404e8f85807a22f5348bc00b53dc2626b261d3d3a44b2`。

- 原生 C 和实际 MIPS 测试对比原 RGB565 路径与合并输出，覆盖四种缩放、224/240
  行、每行强调色、两种像素掩码、调色板变更与边框。32 个 MIPS LCD 比较完全一致。
  测试使用随机像素和调色板，线性模式也验证实际 MIPS/MXU 路径。
  备用 RGB565 路径另验证实际 MIPS 堆申请、退出释放及分配失败时的直接计算回退。
- SGZ2 32 帧、跳 5 帧，与保存的 v0.1.4 BDA 比较：每帧完整序列化状态、CPU/PPU/RAM、
  存档、核心 PCM 以及实际显示的 RGB565 图像一致。核心翻译块指令条目为
  92,373,678 → 89,728,606；它不包含主程序新增的合并 LCD 输出，不等同于实机 FPS。
- 原创精灵测试卡带明确触发精灵零号碰撞与溢出；跳帧 0/2/5 的 CPU/PPU、存档和
  PCM 逐帧一致。另与 v0.1.4 比较 32 帧状态及显示图像一致。该测试不能代表所有
  Mapper、中途寄存器改写和硬件边界情形均已覆盖。
- 实际 MIPS PCM 测试覆盖 22050/32000/48000 Hz、连续相位、未读样本保护、环形
  游标绕回、欠载时同一描述符保持、512 个静音样本及有限淡入，暂停/恢复与音量还原。
  模拟慢显示时核心 20 帧全部执行，临时跳帧没有写入用户设置。
- MIPS 原生启动、ROM 取消、按键、电池保存、即时存档、暂停与恢复、PAL/NTSC 及
  各档跳帧检查通过。公开 CI 增加精灵跳帧和区域/选项回归。
- 最终普通包与诊断包均在独立 H1 V1.41 / QEMU 镜像中运行用户 ROM，完成音乐捕获、
  暂停/恢复和正常退出，原始固件没有被修改。画面检查范围分别为标题/菜单与开场画面，
  不声称已经验证完整战斗流程。模拟器零欠载不代表 H1 实机问题已经解决。

完整固件运行和私有音频只保存在 `build/`；公开摘要见
[证据](evidence/audio-v0.1.5.json)。安装包不包含用户 ROM、私有固件或游戏录音。

## 本地构建与复测

```console
python tools/build.py
python tools/package.py
python tools/build.py --profile
python tools/package.py --profile
```

普通包为 `dist/H1FC-install.zip`，诊断包为 `dist/H1FC-profile-install.zip`。
两者都安装到 `A:\应用\程序\H1FC.bda`。普通包没有逐段计时开销；若仍断音，
诊断包运行 20～30 秒后正常退出，`A:\FC\h1fc.log` 会记录各阶段耗时与欠载细节。

JIT 统计可在本地对自己拥有的 ROM 执行：

```console
python tests/jit_census.py --rom path/to/game.nes --frames 32 --nm path/to/mipsel-none-elf-nm.exe
```

最初 O2/LTO 的静态布局 `__bss_end=0x83ff97b0`，O3/LTO 为 `0x84001690`，
超出本项目链接脚本的静态地址上限，不能把这个数字说成 H1 总内存或堆上限。
颜色表移到堆后，两个有界试验包都能编译。SGZ2 的同一 24 帧、跳帧 0 的核心差分中，
CPU/PPU、序列化状态、PCM 和显示图像一致；O2 主机块指令条目为 84,520,029，
O2/LTO 为 87,200,335，O3/LTO 为 80,529,468。O2/LTO 并未自动减少执行条目，
O3/LTO 的减少也不等同于实机提速，且两个 LTO 版本代码均更大。因此保留 O2 为默认。
主机指令条目、启动次数和录音长度均不能换算成
真实 H1 的提速或断音改善比例。
