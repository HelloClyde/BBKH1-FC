# v0.1.6：事件区间与显示数据路径

本轮性能验证时产品名为 H1 NES Emulator，随后因桌面标签显示不全缩短为 **NES**。
本文保留原被测二进制的名称和哈希；名称调整只涉及 BDA 标题与关于文字，
新包校验见[名称缩短记录](evidence/name-shortening.json)。
本轮优化目标是让完整应用执行更少的工作，保留相同游戏状态、画面与音频。
固定对照为 v0.1.5 改名后的 BDA，SHA-256 为
`c72395522bb9515c037d26631471fb7690943aed502cc0c68438914ec37eb393`。
该二进制、ELF、链接映射和源码副本保存在本地 `build/jit-v4-baseline/`。

## 设计与边界

1. **先确定安全执行区间。** 解码时记录固定周期、纯内存操作、回调与分支边界。
   一段连续指令只有在整个区间内不会遇到 IRQ、APU frame、DMC/DMA 或 Namco IRQ 事件时，
   才能合并时钟更新；事件准入失败时执行原有单指令路径，然后准确返回。
   CPU 预算保留逐指令检查，允许区间只执行前缀后提交，避免短 PPU 时间片反复退回调度器。
   区间不得越过 IO、动态跨页访问、内部跳转入口或可能观察 CPU/时钟状态的回调。
2. **保持精确退出状态。** 运行前的残余 tcount、最后一条指令之前的 PI、DB、PC、寄存器、
   时间戳和所有外设计数都必须与逐指令解释器一致。PC、PI、DB 每条仍准确维护，
   周期债务和 CPU 预算驻留寄存器，完整区间与已执行前缀共用提交代码。区间中不允许 C 回调。
   到事件边界继续调用原处理函数，不跳过 DMA 总线访问或中断延迟。
3. **保留代码有效性检查。** 本轮不删除 PRG 页、代码字节、handler 和 hook 检查。
   热入口省略这些检查需要完整的映射/代码修改失效协议，不以假设 ROM 永远不变代替协议。
4. **缩放复用稳定数据。** indexed 输出保持 palette、emphasis、crop、透明边框和显示模式语义，
   在固定 NES 宽度的常用比例下减少重复取色与索引读取，保留通用和线性缩放路径。
   仍在缓存行内构造输出后写 LCD，避免从非缓存帧缓冲读回。
   256→290、256→310、256→480 的索引映射拆成可重复的小段，保持与 `floor(x*256/w)` 完全一致；
   同一源像素重复输出时只查一次调色板。没有新增动态分配或大查找表。

驻留 P 寄存器的 N/Z、BIT、标志指令减少中转操作，仍在每条指令结束时持有完整标志，未采用延迟标志。
指令覆盖仍为 87 个，默认代码池仍为 1 MiB；本轮没有以新增 opcode 或扩大缓存替代执行成本验证。

本轮优先验证上述两个可独立衡量的执行路径。通用微操作优化器、延迟标志、完整热入口失效协议
属于后续扩展；不把设计方向描述成已完成的功能。

## 测量与验收

- 逐指令、事件边界、寻址/总线顺序和完整序列化核心状态与固定解释器做差分。
- 用真实 MIPS 函数比较所有显示模式、palette 更新、emphasis、裁剪和边框输出。
- 同 ROM、输入、初始存档和设置运行完整 release BDA，比较逐帧 LCD、PCM、CPU/PPU 字段与存档。
- 保留 600 帧开场/有声标题作连续基线，另外用普通按键进入游戏；以截图确认实际覆盖场景。
- 统计启动、编译、核心、显示、PCM、等待、保存与退出的总成本，也报告代码池回收和事件区间命中。
- 完整 H1 固件验证可执行代码、缓存同步、音频、菜单与退出，原始固件和 ROM 不发布。

MIPS 基本块指令入口数衡量结构成本，不是 H1 硬件周期或 FPS。最终收益以实际完成的测试记录为准，
不能把静音启动、核心片段或桌面 JIT 项目的速度换算成真机表现。

## 已完成的验证

最终正常安装 BDA 的 SHA-256 为
`eefbd4c4a169155215aff2fad5132ff0b1510e022c172ee2aeeb90f351a7a9fe`，
诊断 BDA 为 `09ff2cf078b9d08989ba101f2a2db1f7154c3b994f4b0c20e1969556fb5dab55`。
正常包 1,057,256 字节，诊断包 1,067,304 字节；均为不限制运行帧数的 v0.1.6 安装构建。

最终正常 BDA 通过 4,274 个 JIT 差分用例：逐指令 2,809、事件 232、寻址 451、
新运行区间 782；另通过三国志 II、精灵跳帧、DMC、DMC IRQ、PAL 和 Mapper 2 回退的
完整核心序列化、视频、PCM 与存档差分。菜单、即时存档、暂停恢复和退出检查通过。
独立缩放测试执行 102 种配置、408 次真实 MIPS 调用；最近邻输出同时对照独立的索引公式，
线性模式输出和成本保持不变。该单函数测试使用单独测试 BDA，最终发布 BDA 另做完整应用验证。

三国志 II 的 600 帧开场及有声标题场景，完整应用从启动、编译、播放到保存退出的成本为：

| 对照 | MIPS 基本块指令入口数 |
| --- | ---: |
| v0.1.5 | 2,223,330,763 |
| v0.1.6 | 1,976,483,225 |
| 相对上一版减少 | **11.10%** |

该场景逐帧 LCD、PCM、CPU/PPU 状态摘要、实际播放环数据和最终存档完全一致；
两者都显示 600 帧，自动音频追赶为 0。与保留的原解释器包比较，完整应用指令量减少 **25.52%**。
这两个比例使用不同基线，不能相加。

CPU 调度与生成代码合计减少 **3.39%**；缩放函数自身减少 **48.24%**，是本轮完整应用的主要收益。
此缩放分项不包含 LCD 拷贝，也不是整体帧率提升。JIT 编译成本增加约 9.24%，
完整应用统计已包含这项代价；PPU 主循环和背景渲染在本轮没有新增优化。
标题场景 JIT 代码池使用 888,512 字节、回收 0 次；运行区间执行 261,856 次、准入拒绝 15,995 次。

另一段 1800 帧使用[固定普通按键脚本](../tests/scenarios/sgz2-newgame-city.json)进入新游戏，
选择刘备、查看地图、选择并州并打开城市指令表。已查看最终安装 BDA 第 1200、1560、1680 帧截图；
此场景没有进入战斗。

| 新游戏及城市操作，完整应用 | MIPS 基本块指令入口数 |
| --- | ---: |
| v0.1.5 | 6,926,768,853 |
| v0.1.6 | 6,185,754,800 |
| 相对上一版减少 | **10.70%** |

1800 帧逐帧 LCD、核心 PCM、CPU/PPU 摘要及 CPU/APU/PPU/输入/mapper 注册状态表哈希一致，
播放环提交/读取数据和存档也一致。注册状态表是只读观察，含未刷新的 PPU 影子字段，
不能替代完整序列化状态验证。两版均输出 660,352 个核心 PCM 帧，
显示 1790 帧、自动追赶计数 16；追赶检查比较整段总数，不宣称每帧跳帧标志相同。
两次定期存档和正常退出均成功。

城市场景中 v0.1.6 运行区间执行 791,788 次、准入拒绝 55,050 次；
1 MiB 代码池回收由 15 次减至 13 次，最终使用 1,039,680 字节。
这说明长场景仍存在编译与回收成本，后续应结合热块存活统计评估缓存策略，
而不能用标题场景的零回收结果代表游戏内操作。

最终正常包及诊断包也通过完整 H1 V1.41 / QEMU 固件启动、关于、暂停恢复和正常退出测试。
两次音频欠载、丢弃和提交失败均为 0；诊断包 TCU 各阶段 fault 为 0。
正常包显示 963 帧、诊断包显示 905 帧；两次均出现 88 帧自动音频追赶，不能描述为完全不跳帧。
关于页显示 H1 NES Emulator v0.1.6 / HelloClyde，返回桌面后图标透明。
该固件测试覆盖标题动画和应用菜单，不覆盖战斗，也没有测量物理 H1 的 FPS。
原始固件 494 个文件共 941,764,502 字节逐文件校验未改动，测试进程和端口已释放。

可核对的紧凑记录见 [optimization-v4.json](evidence/optimization-v4.json)，包含二进制哈希、
测试数量、完整应用与分项成本、场景覆盖及固件结果。原始逐帧记录、游戏画面和 ROM 留在本地，
安装包仅附带项目原创测试 ROM。
