# 0.1.3 音频修复

用户提供的 SGZ2-CN 日志显示 mapper 19，779 个 CPU/APU 帧中发生 58 次欠载，
音频提交 59 次，而接口错误与样本丢弃均为 0。原实现每次欠载都会取消播放环并
等待重新积累 128 ms 音频，因此持续算力不足时会反复断音。调音量不能改变生产速度。

本版保留环形 PCM 的所有权与清理协议，修改四处：

- N163 低质量混音只在波形相位或输出采样边界变化时结束一段累计，替代每采样
  16 次逐子步相加；频率、采样率及通道数不变时复用相位增量，避免软件 64 位除法。
  补丁仅应用于生成的核心副本；固定上游子模块未改动。
- 核心已经输出 32000 Hz 时直接折合单声道，避免同频重采样的逐采样除法；
  其他输入率保留带跨回调相位的加权重采样。
- 待播量低于 2560 样本（80 ms）时，前端临时采用最多跳 2 帧的显示节奏，
  回升至 4096 样本（128 ms）时恢复用户配置。跳过画面仍执行 CPU/APU 和核心时序。
  自动跳帧计数只在退出时写入日志，不在播放期间逐帧写盘。
- 环容量增至 512 ms，平时仍按 128 ms 待播量控制节奏。自动存档前暂时补足
  256 ms 待播量，再执行写盘；最多等待 120 个核心帧，避免慢设备永远无法自动存档。

## 回归

`tests/n163_mix.py` 从固定上游和生成副本提取真实混音函数，原生编译后对比
24,200 组状态、2,901,800 个采样帧；检查 PCM、相位计数器、波表索引及缓冲尾部。
覆盖 1～8 通道、全部核心采样率、零频率、低频增量溢出和分段回调。
两侧共用确定性非线性幅度查表，生产的 `GetExpOutput` 没有改动。
电脑上的单独计时只用于发现回退，不能作为 H1 帧率。

`tests/audio_smoke.py` 调用最终 BDA 的实际 MIPS 音频函数，验证 32000/48000 Hz
输出与独立重采样参考一致、未读 PCM 不被覆盖、低水位滞回、欠载重建、暂停恢复和
音量清理。另用显示操作消耗额外 PCM 的服务替身验证所有 20 帧 CPU/APU 都运行，
只有画面减少，用户的跳帧配置没有被改写。

完整 V1.41/QEMU 环境使用用户提供的同一 SGZ2-CN ROM、相同固件与操作流程，
录取约 20 秒真实 AIC PCM；同时检查暂停、恢复和正常返回桌面。
测试 ROM、录音及固件留在私有 `build/`，不随安装包分发。
修复前后诊断包的对比，以及最终普通包的独立运行结果，记录在
`docs/evidence/audio-v0.1.3.json`，按各次 BDA SHA-256 区分。

完整固件模拟器不代表真机速度；持续算力不足或存档写盘仍可能造成断音。
尚未用 H1 真机核验本版，不能承诺所有 mapper 19 游戏全速。
