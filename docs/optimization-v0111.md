# 0.1.11：背景展开与显示行复用

基线为 0.1.10 正常版，SHA-256：
`ecb0e11debb7f16df9b7b191c27e427e6f7b2a59563eea9121244a1572884315`。
本轮按完整应用收益选择改动，保留原 JIT、8 MiB 代码缓存、APU 和事件调度。
首次运行仍默认跳帧 1，已有配置和返回键的 B 映射继续保留。

## 采用的改动

PPU 在没有观察回调、fine-X 为 0 的正常背景跨度中，将两个位平面压成两位像素索引，
再用四像素查表展开；每 8 像素从 7 次查表减少到 4 次。
额外查表占 4,608 字节 BSS。调色板变化同步重建查表；CHR 映射仍在当前跨度读取，
不跨 CPU 同步边界保留 CHR 地址。非零 fine-X、特殊 Mapper 钩子及跳帧保持原路径。

显示端缓存最近一帧各行的最近邻缩放结果。复用前完整比较 256 字节源像素、
emphasis、调色板、像素掩码和尺寸；源行变化时重新计算。
缓存命中后仍将整行从普通 RAM 写入 LCD，不读取 LCD，也不依赖菜单前的画面残留。
缓存申请 592,428 字节（约 0.565 MiB），退出释放；申请失败自动走原缩放路径。
线性缩放保留现有 MXU 路径，本轮没有新增 MXU 指令。

PPU LUT 与显示缓存共增加约 0.57 MiB 数据内存。两者仅复用派生像素数据，
不省略 CPU、APU、PPU 时序、Mapper 回调或游戏逻辑。

## 完整应用对照

使用同一《三国志 II》ROM、1800 帧新游戏/城市操作脚本、相同配置与空初始存档。
包括加载、JIT 编译、CPU/PPU/APU、显示、音频供给、周期存档、暂停菜单和正常退出。
城市段为第 1501–1800 帧。配置通过正常文件读取加载，未改写客体状态降低工作量。

跳帧 1 城市段指令量从 781,491,748 降至 722,465,598。
逐帧 LCD、源 PCM、声明状态、播放环、存档及显示节奏严格一致；
共 660,352 PCM 帧、886 显示帧、91 音频追赶帧，前后相同。

固件服务 mock 的音频消费不能证明真机欠载已消除。

## 未采用的 JIT 实验

对 PHA/PHP/PLA/PLP/JSR/RTS 增加覆盖，并尝试单指令调用/返回块连接和简化栈操作。
两版均通过 1800 帧严格差分，但整段只减少 0.157% / 0.135%，
城市段减少 0.322% / 0.480%；第一版还使生成代码从约 4.54 MB 增至 5.41 MB。
收益不足以支持增加这部分复杂度，本版未合入。

只读计数显示城市 300 帧有 289,564 次 CPU 预算返回，现有每次 C 调用进入
native 平均只执行约 4.61 条 6502 指令。下一步需要研究 PPU 与 CPU 的连续执行时间片，
保留精灵零、PPU 寄存器、Mapper、DMC 和 IRQ 的观察边界，不能仅靠扩大覆盖率。
实验源码和原始报告留在本地 build 目录，未进入交付 BDA。

## 正确性与适用范围

- 实际通用/对齐背景跨度及 LUT 构造与上游逐项对比：2,437,120 例；
  跳帧跨度 304,640 例，图块 300,000 例，颜色 65,536 例通过。
- 实际 MIPS 显示函数 102 组冷/热缓存比较及 12 组源读取边界检查通过，
  包括线性、最近邻、裁切、掩码和不同尺寸。
- 最终 BDA 的缓存变更、未对齐源行、末行边界、调色板/emphasis/尺寸变化、
  LCD 被覆盖、释放重建及申请失败共 38 例通过。
- 最终 BDA 的精灵与 DMC IRQ 32 帧核心差分精确，指令量减少 0.40%。
- Mapper9 钩子/CHR 32 帧差分精确，但指令量增加 0.142%：
  新调色板表的维护有成本，非适用路径不保证加速。
- 默认跳帧与旧配置保留、返回键/改键、暂停/即时存档、存档 IO 故障及音频恢复检查通过。

显示缓存首次申请和填充有额外成本；持续变化的画面可能因行比较和复制而更慢。
单独缩放测试在已分配缓存但行未命中时通常增加约 6%–9% 成本，
首次申请的单次调用开销更高；不能把静态城市界面的收益推广到所有游戏。
大量调色板变化或非零 fine-X 的场景也需要分别测量。

## 构建与固件验收

正常版 SHA-256：`4062e52a9b3881a8e41fda3c831064e1ff28573a8552e0e54283b8d4aee2a302`。
诊断版 SHA-256：`0f3a34699b28a69a61e22906f056144d59733e18ccdd7cc06829906dd726f5a9`。
二者分别在独立目录重新构建，与交付 BDA 逐字相同。

完整 H1 固件模拟器中，两版均通过三国志2加载、有声播放、暂停恢复、关于页和正常退出，
且在同一私有 NAND 镜像重启后读取已保存数据并再次正常退出。
关于页为 NES / v0.1.11 / HelloClyde；正常包新增 592,428 字节缓存真实申请成功。
原始固件目录的 494 个文件、941,764,502 字节前后哈希完全一致。
固件验收主要覆盖开场和标题流程，城市性能数据来自前述完整应用脚本对照。

诊断包首次验收时，测试提取器遗漏一个已写入的部分 NAND 单元，读出的日志全为 FF，
因此标准脚本最初失败。保留原失败文件后，对该单元的首尾标签、提交页及逐页标记作
只读检查，恢复出 13,851 字节、195 条连续编号日志，确认 APP_END 为 0。
恢复限定于此次检查的数据单元，不是通用提取器修复；没有修改 NAND 或 BDA。
诊断包重启验收的标准日志提取直接通过。
