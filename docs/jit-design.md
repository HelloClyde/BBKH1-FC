# H1 FC JIT 整体设计与性能验收

目标是减少整帧执行开销，并降低音频欠载。生成代码本身不算性能成果；普通解释器用于正确性对照。
每次优化冻结此前普通版作为性能基线；0.1.13 对照的是 0.1.12 普通版。
独立候选与合并产物分别测量，不把单项百分比相加。

v0.1.6 增加无事件运行区间；实现、与 v3 的对照及验证边界见[优化记录](optimization-v4.md)。
v0.1.9 增加按 ROM bank 保存和恢复编译块的冷路径，见[bank 缓存优化](optimization-v019.md)。
v0.1.10 增加完整区间预算准入、事件边界前缀与有版本的内部入口，见[本版记录](optimization-v0110.md)。
v0.1.13 增加子程序与栈指令，以及区间末尾的固定周期控制流，见[本版记录](optimization-v0113.md)。

## 执行路径

1. 解释器负责未支持指令、IRQ/NMI 入口、特殊取指、可写代码和加密 opcode。
2. 同一 PC / PRG 页 / opcode 执行八次后才尝试编译。冷代码继续解释。短于两条指令的入口记为拒绝，避免反复调用编译器。
3. 入口表直接查找生成函数，包含页身份和 ROM/状态恢复世代。命中时直接调用生成块，取消原版额外的 C 调度函数。
4. 原生块内生成周期计数、PI/DB/PC 更新、寄存器和 RAM 操作。A/P 驻留在 MIPS 保存寄存器；事件调用和退出前写回。已有块内回边直接跳回本块。屏蔽中的普通 IRQ 可继续执行，使用上一条指令的 PI 判断，保留 CLI 延迟；RESET/NMI 和可服务的 IRQ 交还解释器。
5. 一个块最多十六条指令；条件分支、JMP、JSR 和 RTS 结束扫描。有合适后继的热块从入口表验证世代后直接 JR 到目标块的共享栈入口，省去 C 返回和重复 O32 保存。目标仍检查代码页；私有入口在有效凭据下可复用字节/handler 的校验结果，失效时执行完整检查。不适合后继的出口不查表。根据实际生成长度在堆代码池内顺序分配，避免每个小块浪费固定大槽。代码池满且无活跃原生调用时才回收池并更新世代。

返回包的执行计数只有 15 位，回边和跨块连接的上限为 `32768-MAX_OPS`，为下一整块预留计数空间。
到达上限后返回 C 再续跑，不把计数溢出误判为失效标志。人工超帧预算测试关闭音频推进，
验证 16+16+16 条指令闭环跨越该边界；正常帧仍逐帧验证音频。

代码池默认 8 MiB，入口表另占 1 MiB，bank 索引另占 162 KiB，验证表另占 256 KiB；
合计约 9.41 MiB。代码池可选择 1/2/4/8/10 MiB。
它们都使用系统堆，不受静态应用链接范围限制。失败时关闭 JIT 并使用解释器。
当前 CPU PC 入口不匹配时，才在四路 L2 查询同 CPU PC / Page / opcode / epoch 的旧版本。
两级使用移动所有权，原生失效出口清除实际失败块后不能从 L2 复活。
单纯换 bank 返回 C 调度重新绑定，保留旧版本；恢复后仍执行全部内容与时序检查。

## 有效区间内的入口复用

公开原生入口始终执行代码字节和 handler 检查。内部入口另有 PC 对应的版本凭据，
只在一次完整校验后、同一有效区间内复用；它仍检查 PRG 页身份，也不跳过执行预算或硬件事件。
两种入口共用 19 条指令的前导（14 条栈处理加 5 条活跃调用保护），原生块连接可复用当前 O32 栈帧。
原生调用期间允许追加编译，但缓存满时推迟回收，避免递归 CPU 回调覆盖活跃返回地址。
重新编译、bank 绑定、缓存回收及版本号回绕都清除相应凭据。

通常有效区间止于一次 CPU 调用。已核对的 NROM/Namco 普通卡带帧可跨越 PPU 的短 CPU
时间片：须无 PPU、行 IRQ、输入扫描线或 MMC5 特殊钩子，且关闭 overclock。
边界位于输入/cheat 处理之后、PPU 主循环之前，结束于声音输出和前端回调之前。
未知回调先撤销凭据并标记需重验；重新授予凭据前复核上述条件，若回调安装了新的钩子，
后续每次 CPU 返回都会清除凭据。普通 APU 事件只改变已知硬件状态，可以保留代码验证结果。

待执行 DMC DMA 的非批量指令在计时前返回解释器，保留四次取数、偷取周期及当前操作数
可能变化的语义；不能等回调返回后才撤销凭据并继续使用旧常量。
若本次音频事件刚产生新的 DMA 请求，只按原 `ops.h` 语义补完已计时的当前指令，
随后返回 C 调度；不重复基础周期，也不提前执行下一次 DMA。分支和跨页附加周期仍保留。
`$2002` 快速读取块另要求输入扫描线钩子为空。公开入口和外部 CPU 调用仍能发现原地代码修改，
测试不能绕过校验来证明内部入口安全。

## 两种检查层级

通用后端每条指令验证代码页、handler、opcode、可写标志、IRQ 和周期，操作数在硬件钩子之后动态读取。
它保留用于后端差分验证；实测成本过高的通用块不自动准入，游戏继续使用解释器。钩子改变映射时，已执行指令不会重新计时。

快速层只用于固定 FCEUmm 提交下经核对的 NROM / Mapper 19。启用条件包含全部 PRG/DMC 取数区域使用纯 `CartBR`，PRG 不可写，PPU_hook 为 NULL，以及 IRQ 钩子为 NULL 或指定的 `NamcoIRQHook`。该 Namco 钩子只更新 IRQ 计数并置位 IRQ，不修改 ROM 或映射。

快速层在严格块入口验证钩子、overclock 状态、代码页、全部 opcode 和操作数字节（按物理对齐打包为 32/16/8 位加载，仍是逐字节精确比较）；私有入口可按有效凭据复用检查结果。非批量路径仍逐指令验证周期余额与 IRQ，安全 v6 区间使用整段准入和事件前缀。已确认的时钟钩子不会修改代码；可能改变映射的 IO 写只能作为块的最后一条指令，回调后必须退出。因此其之前的操作数与分支目标可以折叠，不变检查可移出块内循环。

绝对地址读取只有纯 CartBR、已确认的 CPU RAM / Namco WRAM 读取，或 `$2002` PPUSTATUS 读取可走快速层；入口验证读取 handler。
v3 增加绝对索引读取，编译时核对 0..255 索引涉及的真实读取与 dummy read handler，每次执行前再检查实际地址的 handler。
索引 dummy read 保留固定上游 `GetABIRD` 的 `target ^ 0x100` 行为，包括 16 位回绕，不在本次优化中改变上游核心语义。
块中途检查失败走正常退出并写回 A/P；只有加载 A/P 前的入口检查可走入口失效路径。
绝对 RAM 写和 INC/DEC 仅在原 RAM handler 下直接生成访存；IO 写调用原 handler 前写回 A/P，调用后重新加载并退出，禁止接入预热的旧映射后继。
间接 JMP 保留指针 xxFF 页内回绕，目标可通过入口表跨 PRG bank 连接到已编译块，仍接受目标完整检查。
JSR 保留低操作数读取、压入返回地址高/低字节、高操作数读取的原顺序；
RTS 保留栈回绕、DB 和返回地址加一回绕，动态目标经过原入口表校验。
PHA/PLA 使用原 CPU 栈 RAM，PLA 保留 N/Z 标志。只有一条指令的 JSR/RTS 入口仍解释，
不为扩展覆盖而放开最少两条指令的编译规则。
其他读取不准入快速层。ROM 页、handler、字节或 overclock 状态变化会退出，不继续使用旧代码。
不符合 Mapper 准入规则的 ROM 不申请 JIT 缓存。CPU run 在批次入口选择原解释器，避免每条指令增加 JIT 查找成本。

## 不能省略的时序

- 保持 opcode 取数 → 基础周期 → Mapper 钩子 → APU 钩子 → PC 更新 → 操作数/数据访问的顺序。
- 保留 `_PI` 的中断延迟、开放总线 `DB`、NTSC/PAL 周期比例、分支附加周期及跨页周期。
- APU 的 frame、DMC、DMA 状态集中在一个 16 字节结构，序列化字段不变。原单指令路径只在 frame/DMC 倒计时均为正且没有 DMA 请求时内联提交计数；任何事件到期，保留未改动的计数并调用原钩子。Namco IRQ 到阈值仍调用原回调。
- v4 在至少三条固定周期、无回调的纯操作上增加区间准入检查：覆盖整个区间长度的 APU/DMC/DMA、Namco IRQ 和待处理中断检查均通过后，在寄存器内累积周期。每条指令仍检查 CPU 预算，并维护 PC、PI、DB；完整区间或任意已执行前缀共用时钟提交。不能证明安全时执行原单指令路径并返回。动态跨页、分支、IO 与 C 回调不进入区间，内部跳转目标划开区间。
- v6 把至少两条纯操作组成区间。完整预算和无事件证明成立时，只做一次 CPU 预算准入，
  合并提交时钟及不可观察的中间 PC/PI/DB；短 CPU 预算仍执行准确前缀。
  整段会跨事件时，按 APU frame、DMC 和 Namco IRQ 的最早期限截取安全前缀，
  不再仅因整段不合格就退化成一条指令。事件触发指令仍走原始时序处理。
- v0.1.13 允许固定周期的 JMP/JSR/RTS 作为安全区间末尾，纯 ROM/直接 RAM 的
  前缀与末尾共用时钟提交。完整区间保留实际目标 PC；短预算前缀以实际执行条数
  判断末尾是否执行，不能仅用 PC 是否等于顺序地址来判断。区间中的控制流
  不直接取尚未提交时钟的内部回边，提交后才进入正常块连接。
  原每次 `_count <= 96` 的短预算规则保留；按首指令周期扩大该规则的实验使完整应用变慢，未采用。
- v0.1.14 将条件分支的固定 2 个基础周期并入纯前缀的预算批次；取分支时的额外
  1/2 周期在提交后保留为 `tcount`，未取分支时的 DB 保持 opcode。
  内部回边在提交后才返回经过预算和事件准入的入口。两指令短块在事件前缀只执行
  第一条、或整段准入不成立时，继续使用原来的逐指令原生守卫和调度，保留正常
  块连接；DMA、IRQ、映射变化仍可立即退出。生成器分别保存批次准入和普通退出的
  跳转修补列表，避免后发射的出口覆盖待修补记录。没有扩大基本块、opcode 覆盖
  或 PPU 时间片；较长条件轨迹和空预算外层返回的实验未取得足够收益，未合入。
- v3 的 C 回退事件调度也对已确认的 Namco IRQ 执行相同无事件路径，保持 16 位回绕；其他 callback 仍原样调用。新增 PHP 等不进入 JIT 的测试，单独检查 C 路径，不用原生测试替代它。
- v6 将 C 路径的 Mapper IRQ、APU frame 和 DMC 合为一次最早期限检查，并缓存已验证的
  Namco IRQ 模式。普通指令仍立即推进可观察计数；到期时调用原始事件处理函数。
  不透明回调前后、真实声音事件及失效的帧准入会撤销期限。回调留下尚未提交的 DMA 周期时
  不授予新期限，避免把 CPU 时间戳误用为 APU 时间。C 回退仍逐指令检查一次期限，
  仅安全原生区间使用整段准入；独立调度收益很小，见 [0.1.10 对照](optimization-v0110.md)。
- 只在证明没有事件且没有观察时钟的回调时合并 APU 计数；不越过事件边界、不替换等待循环、不跳过 DMC 的四次读和偷取周期。分支附加周期仍经 tcount 带入下一次硬件推进。
- 状态恢复、reset、换 ROM 失效缓存；未知 opcode 使用原核心语义。
- 生成代码写入后进行 D-cache 写回、同步及 I-cache 失效，遵守 O32 寄存器保存和延迟槽约定。

## 验收方式

先逐指令比较真实 MIPS JIT 与原解释器的 CPU、RAM、周期和时间戳，再逐帧比较 CPU/PPU、完整序列化状态、存档、画面及 PCM。专门测试钩子在取指后切换操作数页、代码修改、状态恢复、IRQ/NMI 和申请失败回退。jit_event_smoke.py 在 APU frame/DMC 倒计时到期前/当时/之后、DMA 请求、Namco IRQ 阈值及 16 位溢出、分支周期残留等边界比较完整序列化状态，并验证热块直连、屏蔽 IRQ 和后继变化失效。

核心差分包含整帧 CPU/PPU/APU 和编译开销，按函数统计新增成本；另用 `jit_app_benchmark.py`
执行完整的有界 BDA，包含启动、显示缩放、PCM 队列及存档，比较画面、PCM、存档与全部指令量。
v3 的 `jit_app_long_benchmark.py` 直接执行 release BDA，通过普通按键退出；600 帧覆盖非零音频与标题动画，按 60 帧分段。
旧 20 帧三国志2测试处于静音启动，只保留为短回归，不用它代替有声运行阶段。
列出冷启动和热运行。宿主块指令计数是结构开销指标，不等于 H1 的实际耗时或 I-cache 行为。
最后用完整固件确认缓存可执行、PCM、菜单和退出，再交由 H1 真机以同 ROM / 输入 / 显示设置比较 profile 日志及欠载次数。

解释器构建保留用于对照；当前加速构建对外名称为 `NES`，安装为 `H1NES.bda`。性能证据和限制必须与被测 BDA 的 SHA-256 对应；更改代码后重做相关验收。历史记录中的 `H1FC-JIT.bda` 是改名前的文件名，见[命名变更记录](evidence/name-change.json)。
